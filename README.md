# TVNext — IPTV-клиент для Android TV и Windows

Текущий релиз: **TVNext 1.0.14**. [Android APK](releases/android/TVNext-1.0.14.apk) · [Описание релиза](RELEASE_ANDROID_1.0.14_RU.md). Полные исходники находятся в ветке **main**: Android — `apps/android`, Desktop — `apps/desktop`, общие модули — `core` и `features`.

Мультиплатформенное IPTV-приложение (Kotlin Multiplatform + Compose Multiplatform) с поддержкой **Android TV** и **Windows desktop**. Работает с плейлистами формата **M3U**: LIVE-каналы, VOD-медиатека, телепрограмма (EPG/XMLTV), ТВ-гид, архив передач (catch-up), поиск, напоминания и история просмотров.

---

## Возможности

- **LIVE-каналы**: загрузка M3U-плейлистов (несколько источников), группы каналов, избранное, цифровой ввод номера канала, «сейчас идёт» (текущая/следующая передача) под названием канала.
- **VOD / медиатека**: загрузка VOD-плейлистов, категории, постеры, прогресс просмотра, метаданные TMDB.
- **EPG (телепрограмма)**: лёгкий потоковый движок (порт подхода LiteTV) — XMLTV (в т.ч. gzip) парсится скользящим буфером с фильтром только по каналам плейлиста; компактный дисковый кеш, который загружается мгновенно при запуске; описания передач в ограниченном окне времени.
- **ТВ-гид**: сетка передач на дни (вчера… +7 дней), категории каналов, инфо-панель выбранной передачи, линия текущего времени.
- **Архив (catch-up)**: просмотр прошедших передач через механизм провайдера (`catchup-source`, `timeshift` и т.п.).
- **Напоминания**: установка напоминаний на будущие передачи (внутриприложение).
- **Поиск**: по каналам, VOD и телепрограмме.
- **История просмотров**, автопродолжение последнего канала на Android TV.
- **Диагностика**: файл `tvnext_diag.log` в `filesDir` приложения (kill-маркер: определяет, было ли приложение убито системой, а не закрыто штатно).

## Технологии

| Область | Технология |
|---|---|
| Язык | Kotlin (Kotlin Multiplatform) |
| UI | Compose Multiplatform (Material 3, кастомная TV-тема) |
| Навигация | Decompose (компоненты, табы, back-обработка) |
| Архитектура UI | MVI (`MviComponent` / State / Intent / Effect) |
| DI | Koin |
| БД | SQLDelight (плейлисты, каналы, история, настройки, VOD, напоминания) |
| Сеть | Ktor (Android: OkHttp, Desktop: CIO) |
| Плеер Android | ExoPlayer (Media3) |
| Плеер Desktop | mpv через JNA (+ зонды VLC/Compose hw-поверхностей) |
| Форматы | M3U (плейлисты), XMLTV (EPG, gzip/plain) |

## Сборка и запуск

Требования: JDK 17+ (рекомендуется JDK 21), Android SDK (для Android), переменная `ANDROID_HOME` или `local.properties` с `sdk.dir=...`.

```bash
# Android TV (debug APK)
./gradlew :apps:android:assembleDebug
# APK: apps/android/build/outputs/apk/debug/android-debug.apk

# Desktop (сборка)
./gradlew :apps:desktop:assemble

# Desktop (запуск в dev)
./gradlew :apps:desktop:run

# Тесты EPG-парсера
./gradlew :core:iptv:desktopTest --tests "com.tvnext.app.core.iptv.data.LiteXmltvParserTest"

# Проверка кодировки исходников (см. ниже)
./gradlew checkEncoding
```

### Проверка кодировки (checkEncoding)

Проект содержит защиту от порчи кириллицы при перекодировании файлов (`UTF-8 → CP1251 → UTF-8`), из-за которой все русские строки в UI превращались в «е»/«�»-мусор. Задача `checkEncoding` сканирует `apps`, `core`, `features` и `docs` и **падает со списком файлов**, если находит артефакты такой перекодировки. Она выполняется автоматически перед каждой сборкой (`build`), так что не пытайтесь «исправить» повреждённый файл вручную через копирование в буфер обмена — восстановите его из git (перекодируйте обратно `CP1251 → UTF-8`).

### Android TV

Установите `android-debug.apk` на приставку/телевизор. При первом запуске предзаполняются демо-источники (LIVE: vivamax, VOD: viplimeVOD) — работает сразу. Добавить свои источники: **Настройки → Плейлисты**.

- Двойное нажатие **Back** на главном экране — выход из приложения.
- Back в табах — возврат на главный экран.
- Настройки → Данные → «Сбросить все данные» — полный сброс (плейлисты, БД, кеш).

### Desktop (Windows)

```bash
./gradlew :apps:desktop:run
```

Плеер desktop использует mpv (ищет `mpv.dll`/`libmpv` в стандартных местах); при недоступности — пробует VLC и программную поверхность Compose.

## EPG: как это работает

Движок телепрограммы описан в [docs/MODULES.md](docs/MODULES.md#coreiptv) и кратко:

1. **Android**: потоковый разбор XMLTV/gzip с сопоставлением каналов плейлиста и отдельным дисковым SQLite-индексом. Интерфейс запрашивает видимые строки; свежий индекс доступен после перезапуска без обязательного HTTP.
2. **Хранение Android**: рабочий индекс до 96 МиБ с уменьшением при нехватке места, ограниченное окно описаний, очистка поколений и физическое уплотнение. После успешного импорта исходный XMLTV удаляется; для условного HTTP остаётся маленький валидатор. Резерв дополняет отсутствующие каналы. Подробные лимиты и временные файлы — в описании 1.0.4.
3. **Desktop** использует отдельный путь Lite EPG с компактным файловым кэшем; Android-политику хранения к нему не применяем.

## Диагностика «приложение закрывается»

Если приложение исчезает без ошибки, проверьте `filesDir/tvnext_diag.log` (доступен, например, через ADB):

```
adb shell run-as com.tvnext.app cat files/tvnext_diag.log
```

Файл содержит: пометку «PREVIOUS RUN KILLED by system» (процесс убит системой — LMK/native crash), время жизни, размер heap/PSS и БД. Boot-маркер пишется при старте и удаляется только при штатном выходе (`onDestroy`), поэтому фоновый kill после Home не считается крашем.
