# TVNext 0.5.4 для Windows x64

Файл portable: `TVNext-0.5.4-windows-x64-portable.7z`.

Закройте TVNext, распакуйте весь архив через 7-Zip и запустите `TVNext.cmd`. Java и mpv включены. Настройки и история сохраняются в `%USERPROFILE%\.tvnext`.

## Запуск фильмов

В предоставленном логе ускоритель HLS ожидал первый сегмент 10 секунд, завершался по таймауту и передавал исходный поток mpv. После этого фильмы запускались. Эта задержка возникала до прямого воспроизведения.

В версии 0.5.4 обычный запуск сразу использует mpv. Подготовка ускорителя не выполняется и не добавляет 10 секунд ожидания. Начальная буферизация самого потока остаётся и зависит от его скорости.

В **Настройки → Воспроизведение → Загрузка фильмов** доступны два режима:

- **Обычная** — прямое подключение, включено по умолчанию, в том числе при обновлении с 0.5.3.
- **Параллельная** — загрузка нескольких сегментов одновременно. Может помочь при ограничении скорости одного соединения провайдером. Требует предварительной подготовки; при неудаче остаётся переход к прямому потоку.

Выбор сохраняется после перезапуска приложения и применяется при следующем запуске фильма. Текущее воспроизведение не перезапускается. Названия переведены на английский и китайский.

Дополнительно устранена гонка между командой открытия фильма и событием готовности mpv. Раннее событие теперь дожидается сохранения идентификатора потока и не оставляет готовый фильм в состоянии загрузки.

## Кадры и постеры передач

Запросы метаданных медиатеки раньше продолжали работать после отмены вызывающей задачи и могли занять все четыре места в общей очереди TMDB. Новые передачи ожидали освобождения очереди, тогда как кешированные картинки оставались доступны.

Теперь запрос отменяется, когда он больше никому не нужен. Один оставшийся потребитель продолжает получать общий результат. Весь запрос Windows ограничен 20 секундами; отмена не записывается в кеш как ошибка. Временная ошибка кешируется на 10 секунд вместо минуты. Открытая карточка повторно запрашивает метаданные после ошибки и может получить адрес нового кадра без закрытия описания.

В терминале выводятся статусы метаданных, HTTP-коды картинок и ошибки mpv. В новых сообщениях полные адреса и заголовки авторизации скрываются.

## Проверки

Отдельно воспроизведены раннее событие готовности фильма и блокировка очереди четырьмя отменёнными запросами медиатеки. Проверяются переключение режимов без перезапуска текущего фильма, сохранение настройки и все три языка, восстановление кадра в открытой карточке после ошибки, отсутствие отрицательного кеша после отмены.

Все 336 автоматических тестов прошли; общие изменения прошли компиляцию для Android и проверку кодировки. Проверки выполнялись на Linux. Прямой запуск через mpv подтверждён предоставленным пользователем логом версии 0.5.3 после таймаута ускорителя. Физический запуск новой версии Windows здесь не проверен. Android APK в этом выпуске не обновляется.
