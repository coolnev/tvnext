## Соединения TMDB

В предоставленном логе после нескольких переключений каналов возникали `ConnectException` у обоих CDN картинок и обоих адресов API TMDB. В этот момент запрос метаданных также возвращал ERROR без адреса кадра. Наличие текста на экране само по себе не подтверждает сетевой доступ: текст может поступать из EPG или кэша.

Теперь плейлисты/EPG, API TMDB и изображения используют три отдельных сетевых клиента. В Windows для API и картинок используется OkHttp с повторными подключениями и быстрым перебором IP-адресов сервера. Загрузка EPG не занимает их соединения. Лимит запросов к одному серверу учитывает шесть фоновых постеров и три источника кадра: зависшие ответы постеров не занимают все места, нужные открытой карточке. Android уже использовал OkHttp; в нём также выделены отдельные клиенты метаданных и изображений.

Основной и резервный официальные адреса API из версии 0.5.5 сохранены. Их успешный адрес используется первым в следующих запросах. В обеих версиях отменённый запрос перестаёт занимать очередь, а весь поиск метаданных ограничен 20 секундами, включая ожидание очереди.

## Картинки в Windows и Android

Обе платформы используют общий загрузчик с официальными CDN `image.tmdb.org` и `media.themoviedb.org`. Резервный адрес начинает работу через 300 мс; успешно ответивший CDN пробуется первым для следующих кадров. Если он перестал работать, другой остаётся доступен. Ненужные запросы и тела ответов отменяются, загрузка ограничена по времени и объёму. HTML/JSON-заглушки не принимаются за изображение. Заголовки Cookie и Authorization исходного адреса не передаются резервному CDN.

Открытые карточки повторяют загрузку метаданных и картинок после временных ошибок на обеих платформах. Для Android добавлены эти повторные попытки и отдельная очередь кадров, чтобы они не ожидали загрузки логотипов каналов. Ошибки метаданных кэшируются на 10 секунд. Рабочее изображение сохраняется, пока подгружается более приоритетный источник; переключение на другую передачу сбрасывает старое изображение.

Исправлена воспроизведённая ошибка файлового кэша: неудачная запись на диск больше не скрывает успешно скачанный кадр. Он отображается и остаётся в памяти. Ошибка чтения кэша также не мешает новой загрузке. Файловые операции перенесены с вычислительного диспетчера на диспетчер ввода-вывода.

## Проверки

366 тестов прошли без ошибок. Проверены отказ первого IP и подключение через следующий, независимость сетевых клиентов, восстановление после закрытия сервером соединений, смена рабочего CDN, недоступность файлового кэша, многократная отмена настоящих HTTP-загрузок и последующая загрузка новых кадров. Проверка HTTP-соединений выполняется и с прежним CIO, и с новым OkHttp; она сама по себе не доказывает, что в исходном логе была утечка соединений.

В Android host-наборе 11 тестов, включая проверки общего загрузчика: резервный CDN, отмена обоих запросов при закрытии карточки, временный сбой и неподходящие ответы. Это тесты на компьютере, без запуска интерфейса на телевизоре. APK собран как недебажный release с минификацией; подпись совпадает с предыдущим APK. Для распространения вне тестирования по-прежнему нужен собственный релизный ключ.

Физический Windows-компьютер и Android TV для проверки здесь недоступны. Облачный прокси блокирует живые запросы к TMDB, поэтому восстановление доступа именно в сети пользователя новой сборкой пока не подтверждено.

## Установка

Windows: полностью закройте TVNext, распакуйте весь portable-архив в новую папку и запустите `TVNext.cmd`. Java 21 и mpv включены. Настройки и история остаются в `%USERPROFILE%\.tvnext`.

Android: установите APK поверх прежней версии. Приложение имеет номер **0.5.6**, versionCode **20**, прежний идентификатор и подпись; данные приложения удалять не нужно.
