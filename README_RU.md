# TVNext 0.5.14 — Android

## Быстрое переключение каналов

Автоматическая информационная плашка после смены канала больше не забирает фокус на свои кнопки. Пока она видна, следующие нажатия вверх/вниз продолжают переключать каналы; ждать её исчезновения не требуется. Панели, открытые пользователем стрелкой вправо или при управлении архивом, сохраняют интерактивные кнопки и прежнюю навигацию.

## Аппаратный приоритет в «Автоматически»

Ранее в автоматическом режиме аппаратный и FFmpeg-рендерер одновременно участвовали в выборе дорожки, и поддержка формата могла привести к выбору программного декодера даже при работоспособном аппаратном. Теперь начальный путь видео совпадает с явным аппаратным режимом. При отказе цепочка идёт последовательно:

1. Аппаратные декодеры устройства.
2. Системный программный MediaCodec.
3. Программный FFmpeg.

В автоматическом режиме неподдерживаемая видеодорожка обрабатывается и тогда, когда Media3 продолжает воспроизводить звук без явной ошибки видео. Отслеживание остановившихся видеокадров также продвигает по этой ограниченной цепочке. Для нового канала попытки начинаются заново с аппаратного режима. Запоздалые ошибки от заменённого плеера/источника не применяются к новому каналу.

Звук и видео восстанавливаются независимо. Аппаратное видео может сочетаться с программным звуком. Ошибка аудиодекодера определяется по типу рендерера даже при отсутствующем MIME; она больше не должна ошибочно переводить видео в программный режим. Системные программные декодеры c2.android/OMX.google теперь правильно отмечаются как программные в диагностике.

Явные режимы «Аппаратное» и «Программное» сохраняют свой смысл. После обновления выберите «Настройки → Воспроизведение → Декодирование видео → Автоматически», чтобы использовать новую цепочку. Сохранённый ручной выбор не переопределяется обновлением.

Если аппаратный блок телевизора не поддерживает конкретный профиль/формат, программное декодирование тяжёлого 4K всё ещё может быть медленным. Универсальный смешанный режим не добавляет чипу поддержку отсутствующего видеоформата; разделение аппаратного видео и программного звука помогает при проблеме именно звуковой дорожки.

## Исправлен адрес резервного API

При проверке ключа в 0.5.13 приложение получало HTTP 301 от api.kinopoisk.dev. Пользователь подтвердил адрес после перенаправления: https://api.poiskkino.dev/v1.4/movie?limit=1; браузер без ключа получал от него ответ о необходимости токена (401).

Теперь проверка соединения, поиск фильмов и запрос подробностей сразу обращаются к https://api.poiskkino.dev/v1.4/. Запросов к старому api.kinopoisk.dev больше нет. Это убирает обращение к адресу, на котором возникал 301, и лишний переход перед каждым запросом.

Поле в настройках по-прежнему называется «Kinopoisk.dev · резерв». Сохранённый API-ключ используется автоматически; вводить его повторно и очищать данные не требуется. Сам ключ не включён в сборку. Проверка выполняется через «Настройки → Медиатека → Проверить Kinopoisk.dev». Дефисы в ключе сохраняются.

## Обработка перенаправлений

Допускаются HTTP 301/302/303/307/308 внутри того же HTTPS-сервера api.poiskkino.dev, на стандартном порту 443. Исходные параметры поиска и проверки сохраняются, если они не заданы в новом адресе. Относительные адреса разрешаются относительно текущего пути.

Переходы на другие серверы, HTTP, нестандартные порты и адреса со встроенным логином/паролем блокируются до отправки ключа. Обнаруживаются циклы; разрешено не более трёх переходов. Общие сроки запросов из 0.5.13 сохранены. Подробные сообщения об ошибках, обработка null и сохранение кэша также сохранены.

## Проверки и установка

630 проверок без ошибок и пропусков. Проверены непосредственные обращения к новому серверу при проверке, поиске и загрузке подробностей, переход на резерв после ошибки TMDB, HTTP 301 и относительный 307 с сохранением параметров, запрет утечки ключа при смене адреса, циклы и ограничения цепочек. В APK дополнительно проверяется наличие нового API-адреса и отсутствие старого. Проверены четыре быстрых переключения с видимой автоматической плашкой и сохранением фокуса, порядок и ограничение попыток декодирования, независимость аудио/видео, сброс между каналами и определение аудиоошибок по реальным константам Media3.

Проверки выполнены на Linux/Xvfb с Android host-тестами и HTTP-моками. Физический телевизор не проверялся. Облачный прокси блокирует подключение к реальному API до передачи запроса, поэтому действительность пользовательского ключа из этой среды не подтверждена. Адрес назначения подтверждён пользователем, маршрутизация приложения проверена тестами.

TVNext-0.5.14-release.apk: версия 0.5.14, код 28, minSdk 24, targetSdk 36. Release-сборка с минификацией, без debuggable, с прежней тестовой подписью; arm64-v8a, armeabi-v7a, x86, x86_64. Устанавливается поверх предыдущей версии с сохранением данных.

Windows не пересобиралась; опубликованная версия остаётся 0.5.10.
