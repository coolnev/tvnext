# TVNext 0.2.11 — восстановление потока и описание справа

Android TV и Windows x64.

## Восстановление воспроизведения

- Временные сетевые ошибки больше не исчерпывают лимит из трёх перезапусков. Приложение продолжает попытки восстановления выбранного потока, пока просмотр не отменён. Паузы между попытками растут: 1, 2, 4, 8, 15, затем максимум 30 секунд; время самой загрузки учитывается отдельно.
- Достаточно длительное действительно продолжающееся воспроизведение возвращает короткий начальный интервал. Мгновенное появление READY не сбрасывает защиту от частых повторных запросов.
- Прямой эфир повторно открывается у текущего live-края. Архив и фильмы сохраняют позицию, в том числе когда движок во время повторного открытия временно сообщает нулевое время. Перемотка, сделанная во время ожидания, применяется при восстановлении.
- Зависание загрузки, буферизации или остановившегося времени воспроизведения обнаруживается даже без явной ошибки движка. Для первого открытия потока даётся больший срок, чем для последующего затыка.
- Во время восстановления показывается индикатор и номер попытки вместо окончательной сетевой ошибки. Пауза отменяет отложенный перезапуск; остановка, закрытие приложения и смена потока отменяют старые попытки. Запоздалое событие предыдущего канала не должно открывать его снова.
- Постоянные ошибки доступа HTTP 401/403 и неподдерживаемого формата остаются явными ошибками. Настоящее окончание фильма не превращается в бесконечный повтор последних секунд.

## Android

- PlayerView сохраняет изображение при сбросе источника, чёрная шторка выключена. При затыке дополнительно выполняется одна ограниченная копия текущего кадра; она удерживается до прихода нового кадра. Постоянного захвата экрана нет. При смене канала/фильма и остановке изображение предыдущего потока удаляется. До первого полученного кадра сохранённого изображения, естественно, нет; на отдельных устройствах захват поверхности может быть недоступен.
- LIVE: минимальный буфер 5 секунд, максимальный 30, старт после 2 секунд, после затыка — запас 5 секунд; размер буфера ограничивается настройками LoadControl. Это немного увеличивает начальное ожидание ради более устойчивого просмотра. Для архива и фильмов сохранён отдельный больший запас.
- Media3 получает дополнительные внутренние попытки загрузки сегментов. Возвращение доступной сети может ускорить уже отложенное переподключение. Работа в фоне и пауза не запускают самовольное воспроизведение.
- Восстановление видеодекодера AUTO и резервный программный декодер сохранены отдельно от обработки сетевых проблем.

## Windows

- Прямой эфир восстанавливается и при неожиданном EOF, и при ошибке. Последний готовый кадр сохраняется при повторном открытии.
- Исправлен размер/расположение полей структуры `mpv_event` при чтении через JNA, и размер `size_t` для шага строки изображения на Windows x64.
- libmpv сначала инициализируется, затем создаётся контекст вывода, как требует его API. Пауза/продолжение используют существующий экспорт API, а не отсутствующий `mpv_set_property_flag`.
- Поздние события отсеиваются по идентификатору записи плейлиста; отмена, обработка состояния и освобождение нативных ресурсов согласованы. Существующий HLS-прокси фильмов и его кэш используются при переподключении.

## Списки и описание

- Категории «Контура» расширены со 156 до 216 dp. Длинным названиям разрешены две строки при прежнем размере шрифта.
- Описание справа автоматически прокручивается вверх и обратно: начальная пауза 3 секунды, затем медленное движение и паузы по 5 секунд на концах. То же поведение используется общим компонентом описания на обеих платформах.
- Под незагруженный или отсутствующий постер место больше не резервируется. Текст начинается сразу под заголовком/временем передачи. Только успешная загрузка постера сдвигает его вниз.

## Проверка и установка

Проверены обрывы больше трёх раз, интервалы восстановления, зависание буфера, настоящая концовка фильма, сохранение и изменение позиции, пауза/остановка/смена потока, старые события, ABI событий libmpv, прокрутка в обе стороны, отсутствие пустого места до загрузки постера и после ошибки загрузки. Проверки libmpv используют тестовый нативный адаптер и настоящую JNA-разметку памяти; UI выполняется в Linux/Xvfb. Физический TCL, сетевые сбои на нём и реальный запуск под Windows в этой среде недоступны. Краткие сбои провайдера и соединения обрабатываются автоматически, но доступность самого источника приложение гарантировать не может.

APK — оптимизированная release-сборка без отладки, с прежним тестовым сертификатом; устанавливается поверх предыдущей версии с сохранением настроек. Windows: распакуйте весь архив и запустите `TVNext/TVNext.cmd`; Java включена.

Снимки интерфейса используют тестовое расписание и условную иллюстрацию, а не настоящий кадр фильма.
