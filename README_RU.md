## EPG в обеих версиях

Воспроизведены ошибки, из-за которых неполное расписание могло сохраняться надолго:

- В Windows ошибка чтения потока превращалась в конец файла. Завершённые первые передачи могли попасть в кэш после обрыва остального XML.
- Парсер не требовал закрытия корневого элемента XMLTV; обрыв между завершёнными передачами считался допустимым.
- Для свежести кэша хватало одного канала с будущими передачами. Остальные каналы могли остаться с воскресной программой.
- Передачи на завтра также делали кэш свежим, даже когда сегодняшней программы не было.
- В Windows несколько источников использовали общий кэш; обновление другого плейлиста могло очистить предыдущий.

Теперь обе версии принимают только завершённый XMLTV и публикуют обновление после полной проверки. Незавершённая загрузка сохраняет прежнюю программу. Свежесть проверяется для каждого ранее сопоставленного канала и для оставшейся части сегодняшнего дня. Передачи завтрашнего дня сами по себе не закрывают отсутствие сегодняшних данных.

В кэше также сохраняются сопоставленные каналы из заголовка XMLTV, даже если в первом ответе для них ещё нет передач. Это отдельно проверено на BCU Kinozal Premiere 1–3 HD: недостающие передачи запрашиваются повторно и после перезапуска приложения.

При полном XML, в котором источник временно перестал отдавать часть каналов, прежние данные этих каналов сохраняются. Если новый фрагмент начинается в будущем, доступные сохранённые передачи перед ним также остаются. Такой кэш отмечается как частичный и повторно проверяется через 5 минут. При повторении неполного ответа интервал увеличивается до часа, чтобы не скачивать большой файл каждую минуту. Ручное обновление выполняется сразу.

Проверка необходимости обновления выполняется раз в минуту. Полный свежий кэш при этом повторно не скачивается. Для каждого плейлиста выделен отдельный кэш. Существующий кэш Android сохраняется; старый общий кэш Windows переносится по плейлистам, чтобы программа оставалась доступна до следующей успешной загрузки. Сохранённые кэши прежнего формата автоматически перепроверяются. Операции чтения потока выполняются на диспетчере ввода-вывода.

## Изображения Windows

Предыдущие изменения движков JVM не подтвердили устойчивую работу на компьютере пользователя. В Windows 10/11 API TMDB и картинки теперь загружаются через системный `curl.exe`, использующий системные DNS и TLS/Schannel. Соединения не зависят от состояния DNS, TLS и пула соединений JVM. Адреса и заголовки с ключами передаются через stdin и не попадают в аргументы процесса или новые сообщения журнала.

Каждый запрос имеет конечное время ожидания и ограничение размера. Отмена запроса завершает процесс и удаляет временные файлы. HTTP-коды и JSON ошибок сохраняются, поэтому проверка ключа TMDB продолжает работать. Официальные резервные адреса API и CDN, повторные попытки и скрытие пустого места под отсутствующую картинку остаются.

В терминале Windows строка `[WindowsHTTP] transport=system-curl` подтверждает выбранный транспорт. При системной ошибке выводятся только имя сервера, код curl и тип сбоя: DNS, соединение, TLS, таймаут или обрыв тела. Если системный curl отсутствует, используется прежний JVM-клиент с отдельным сообщением об этом. TLS-проверка сертификатов не отключается.

Android сохраняет OkHttp для изображений; изменения EPG и его кэша применены к обеим платформам.

## Проверки и пределы проверки

384 автоматических теста прошли без ошибок. Новые проверки покрывают обрыв XML, неполную понедельничную программу, отсутствие сегодняшних передач при наличии завтрашних, сохранение текущей передачи, повтор после частичного ответа, независимость источников и перенос прежнего кэша.

Для системного HTTP проверены 50 последовательных запросов с закрытием соединений сервером, 20 циклов отмены настоящих загрузок с последующим декодированием новых PNG, gzip, редиректы, JSON с HTTP 401, таймауты, завершение процессов и отсутствие ключа в аргументах запуска. Проверки выполнялись на Linux с локальным HTTP-сервером; реализация Schannel на физическом Windows-компьютере здесь не проверена. Android APK также не запускался на физическом телевизоре. Доступ к живому TMDB и текущему EPG провайдера из облачной среды не подтверждён.

Приложение не может создать отсутствующие в ответе провайдера передачи. Оно сохраняет имеющиеся данные, сообщает о частичном обновлении и повторяет запрос.

## Установка

Android: APK **0.5.8**, versionCode **22**, недебажная release-сборка с минификацией и прежней тестовой подписью. Установите поверх предыдущей версии.

Windows: полностью закройте приложение, распакуйте весь portable-архив в новую папку и запустите `TVNext.cmd`. Java 21 и mpv включены. Данные приложения удалять и кэш вручную очищать не требуется.
