# TVNext 0.5.5 для Windows x64

[Скачать Windows x64 portable 0.5.5](https://github.com/coolnev/tvnext/raw/refs/heads/artifacts/windows-0.5.5-20261026/TVNext-0.5.5-windows-x64-portable.7z).

Закройте TVNext, распакуйте весь архив через 7-Zip в новую папку и запустите `TVNext.cmd`. Java 21 и mpv включены. Настройки и история остаются в `%USERPROFILE%\.tvnext`.

## Подключение к TMDB

Раньше поиск и описания использовали только `api.themoviedb.org`, включая все повторные попытки. Теперь приложение также использует официальный адрес `api.tmdb.org`. Если основной запрос завис, резервный начинается через полсекунды; при сетевой ошибке или неправильном ответе — сразу. Успешный адрес используется первым в следующих запросах. Ненужные запросы отменяются. Ключ передаётся только официальным серверам TMDB.

Проверка соединения использует тот же механизм, что поиск и загрузка описаний. Она проверяет структуру ответа, поэтому HTML-страница блокировки с кодом HTTP 200 больше не считается успешным подключением. Пустое поле собственного ключа использует настроенный ключ по умолчанию, как и загрузка описаний.

Исправлена обработка JSON-ошибок: ответ без списка результатов больше не принимается за пустой поиск. Такой ответ раньше мог сохраняться как «фильм не найден» на сутки. Теперь используется другой адрес или возвращается временная ошибка, которую карточка может повторить. Уже сохранённые записи автоматически не удаляются; после обновления при необходимости используйте **Настройки → Обслуживание → Очистить кэш TMDB**.

В **Настройки → Медиатека → Проверить соединение** отдельно показываются неверный ключ, отсутствие связи, блокировка доступа, временная недоступность сервиса и неправильный ответ. Сообщения переведены на английский и китайский. В терминале выводятся адрес сервера и тип ошибки без ключа и поискового запроса.

Для картинок сохранены параллельная проверка официальных `image.tmdb.org` и `media.themoviedb.org`, ограничение времени загрузки и повторные попытки. Исправления получения метаданных позволяют получить адреса новых кадров и постеров, даже если один адрес API недоступен.

## Проверки и ограничения

Автоматические проверки воспроизводят зависший основной сервер, получение описания и адреса кадра через резервный, HTML- и JSON-заглушки, неверный ключ, HTTP 403/429/503, отмену обоих запросов при закрытии и восстановление после полного обрыва. Проверяется конечное время ожидания двух молчащих серверов и сообщения в настоящем экране настроек на трёх языках.

Все 344 автоматических теста прошли; общие изменения также скомпилированы для Android. Проверки выполнялись на Linux. Облачный сетевой прокси отклоняет запросы к TMDB с HTTP 403 ещё до соединения с сервисом. Поэтому работоспособность живого TMDB, действительность встроенного ключа и доступность серверов на компьютере пользователя здесь не подтверждены. Физический запуск этой сборки на Windows не проверен. Android APK в этом выпуске не обновляется.
