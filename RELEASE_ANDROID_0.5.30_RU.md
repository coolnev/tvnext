# TVNextR 0.5.30 — исправление EPG и вылета настроек

В 0.5.29 Android-драйвер SQLite отклонял `PRAGMA busy_timeout=3000`, выполненный как `executeUpdateDelete`. Этот PRAGMA возвращает строку. В результате база EPG не открывалась, передачи отсутствовали, а необработанное исключение при открытии настроек завершало приложение. Настольный JDBC-драйвер не воспроизводил эту особенность Android.

Удалены ручные PRAGMA новой базы EPG. Пул соединений и WAL настраивает FrameworkSQLiteOpenHelper. Формат, имя и расположение кэша сохранены; очищать данные приложения не требуется. Настройки также обрабатывают ошибку чтения кэша и показывают её в разделе EPG. Наблюдатель изменения плейлистов защищён от необработанной ошибки чтения.

Добавлены регрессионные проверки с AndroidSqliteDriver, FrameworkSQLite и native SQLite на Android API 28 и 35: открытие EPG из настроек, загрузка XMLTV, чтение текущих и архивных передач через новый экземпляр репозитория без повторного HTTP, работа настроек при недоступном кэше. До исправления два исходных сценария падали; после исправления все шесть проверок проходят. Дополнительно проходят 202 IPTV-теста, четыре теста настроек, checkEncoding, assembleRelease и lintVitalRelease.

Пакет `com.tvnext.app.recovery`, версия `0.5.30-recovery-preview`, versionCode 530. Release, debuggable=false; прежняя подпись сохранена для обновления поверх 0.5.29. APK — `releases/android/TVNextR-0.5.30.apk`, сводка — `releases/android/validation-0.5.30.json`. Исходники и оригинальный ZIP сохранены на GitHub.

Проверка самого APK в Android 9 эмуляторе: воспроизведён вылет настроек у 0.5.29; выполнено обновление на 0.5.30 без очистки данных; настройки открываются, загружен локальный XMLTV (1 канал, 3 передачи). После остановки процесса и отключения источника список показывает вчерашнюю, текущую и следующую передачи. Вправо с канала открывает этот список. После перезапуска нет FATAL EXCEPTION или ANR; XMLTV запрошен один раз за весь сценарий. Скриншоты и журнал старого вылета сохранены в validation-0.5.30/.

Ограничение эмулятора: нет KVM. Первая загрузка одновременно со сменой размера виртуального экрана и вводом Menu вызвала Input dispatch ANR; стек UI ожидал ThreadedRenderer.nLoadSystemProperties. Поэтому эти проверки не подтверждают скорость старта и плавность видео на физическом ТВ. Сам видеопоток тестовый источник не предоставляет.
