# TVNext 1.0.21 — защита видеовывода Realtek

Пользователь подтвердил возврат зацикленных кадров на 1.0.20: аппаратный `OMX.realtek.video.decoder`, AVC, вывод **TextureView**. Дополнительно сообщил о непостоянной неровности 4K, без устойчивого воспроизведения на одном канале.

В 1.0.20 защита при смене поверхности была убрана слишком широко. Теперь повторное сообщение о той же Surface сохраняет декодер и уже принятый ключевой кадр. При фактической смене Surface, затрагивающей защищённый TextureView, аппаратный декодер освобождается перед передачей нового вывода: небезопасный vendor setOutputSurface не используется. Для нативного SurfaceView и других вендоров сохраняется обычная обработка Media3. Обычное переключение канала не пересоздаёт TextureView через Compose.

Закрыт дополнительный путь: внутренняя смена входного формата могла переиспользовать или сбросить старый кодек, минуя защиту при seek/disable. Для затронутого аппаратного TextureView решение Media3 о переиспользовании теперь возвращает REUSE_RESULT_NO / DISCARD_REASON_WORKAROUND. Media3 сохраняет порядок drain до конца старых данных и затем пересоздаёт декодер. Seek, disable и догон до ключевого кадра сохраняют свою защиту от flush. OMX.realtek распознаётся прямо по имени, независимо от строки производителя устройства. Программные декодеры и нативный вывод этой защитой не перенастраиваются.

Для 4K исправлена область действия обхода Box из 1.0.20. Изученный синхронный режим очереди теперь привязан к конкретному источнику и кодеку. Переход на другой канал возвращает его обычную очередь Media3, даже если ExoPlayer, аппаратный Realtek и параметры UHD совпадают. Возврат к проблемному каналу сохраняет только его собственный профиль. Общего переключения очередей всех 4K-каналов больше нет. Профиль хранится в памяти, условия его обучения не расширены.

Анимация, нативный вывод UHD/HDR, AFR и его настройки сохранены. Ожидание первого видеокадра из 1.0.20 сохранено; фиксированной задержки запуска не добавлено. Разрешение и битрейт не снижались.

**482 автоматических проверок прошли**: 83 Player, 67 метаданных, 109 Channels, 7 Home, 216 Android API 28/35. Проверки фактической смены поверхности и настоящего Media3 onInputFormatChanged выполнялись с теми же финальными тестами против исходного рендерера 1.0.20: четыре ожидаемых падения на двух API. На новом рендерере проходят. Проверено, что одинаковая поверхность не вызывает release; затронутая новая поверхность не вызывает setOutputSurface; смена формата запрашивает drain/reinitialize; нативный вывод и другие вендоры сохраняют обычную обработку. Проверены переназначение профиля при реальном переключении контроллера и фабрика очередей при переходе между несколькими UHD-каналами и возврате к Box.

Release, lintVitalRelease, encoding, Desktop compileKotlin, подпись, ZIP и zipalign16KiB прошли. PNG, Android TV banner и нативные библиотеки совпадают с 1.0.20. Пакет com.tvnext.app, versionCode 1021, прежняя подпись. APK: releases/android/TVNext-1.0.21.apk. SHA-256 `7dae9898ab0c643d6833f402f6b68e1a8c1134773413c04a347aa2a5ff58afb9`. Исходники `a9155ce2728ae06cf7992f59467ce008dd5c0eed`.

Физический Realtek/TCL здесь не проверен: автоматические проверки выполняют настоящий Media3 с управляемыми адаптерами и не воспроизводят сам драйвер телевизора. Плавность на устройстве и исчезновение зацикливания на нём пока не подтверждены. Исходные байты Box недоступны из этой среды. Windows-установщик не собирался.
