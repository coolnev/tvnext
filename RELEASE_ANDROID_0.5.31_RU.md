# TVNextR 0.5.31 — скачивание EPG с докачкой и отдельной обработкой

В 0.5.30 HTTP-соединение оставалось открытым на всё время разбора XMLTV и записи в SQLite. Медленный импорт сдерживал чтение сети; фиксированные паузы при воспроизведении добавляли время к обработке каждого большого файла. Уход Activity в фон и порог общего Java heap прерывали даже ограниченный по памяти импорт. Резервные источники могли скачиваться после того, как основной уже обеспечил программу видимых каналов.

Теперь Android сначала сохраняет исходный XMLTV/gzip в приватный файл, закрывает HTTP, затем обрабатывает файл на отдельном фоновом потоке. Размер буферов ограничен; XML целиком не загружается в память. Скачивание не ждёт SQLite. Разбор и запись выполняются вне потока интерфейса; чтение готового EPG остаётся независимым.

- Незавершённый файл и ETag/Last-Modified переживают остановку процесса. При обрыве используется HTTP Range + If-Range. Если сервер игнорирует диапазон или меняет документ, старый префикс не смешивается с новым ответом.
- Четыре попытки с паузами для временных ошибок; 401/403/404 не повторяются подряд. Проверяется Content-Length и Content-Range. Gzip-файл и HTTP Content-Encoding учитываются отдельно, чтобы смещения докачки оставались корректными.
- Полностью скачанный файл сохраняется до успешного коммита поколения базы. Сбой SQLite не требует заново скачивать источник. Неполный/повреждённый XMLTV не становится свежим кэшем.
- Уход Activity в фон не отменяет начатую обработку. Новые задачи по-прежнему ждут открытия приложения; после завершения процесса следующая загрузка продолжает сохранённый файл. Старая программа доступна, пока новое поколение обрабатывается.
- В настройках различаются «Скачивание EPG: … МБ» и «Обработка EPG: … передач». Исправлена проверка резервов: следующий источник пропускается, если видимые каналы уже обеспечены текущей программой, в том числе при ручном обновлении.
- Парсер больше не ищет отсутствующий channel-тег по всему непрочитанному хвосту на каждой передаче. Запись идёт транзакциями до 512 строк/256 тысяч символов текста и SQL-пакетами до 64 строк (640 параметров, совместимо с лимитом SQLite 999). Из отдельной EPG-базы убраны дублирующий и неиспользуемый индексы; основная база приложения не меняется.
- Фоновый приоритет сохранён. Пауза при активном видео сокращена с 14 до 1 мс на 256 передач. Порог занятой памяти всего приложения больше не обрывает импорт, чей собственный буфер ограничен.

Проверки: 205 IPTV-тестов, 4 Settings-теста, 22 Android-проверки на API 28/35 с native SQLite. Среди сценариев: обрыв и докачка, перезапуск с частичным файлом, сервер без Range, неверный Content-Range, сохранение готового файла при сбое индекса, оба варианта gzip, отсутствие лишних повторов 404 и резервных источников. Импорт 20 000 передач завершается после ухода Activity в фон при установленном состоянии активного видео. Отдельно прочитан файл 64,8 МБ / 50 000 передач с полными описаниями. Результаты машинных измерений не являются оценкой скорости телевизора.

Пакет `com.tvnext.app.recovery`, `0.5.31-recovery-preview`, versionCode 531. Release, debuggable=false, подпись сохранена. Установка поверх 0.5.30 без сброса данных. APK и полные исходники сохранены на GitHub. Сводка и подтверждения — `releases/android/validation-0.5.31.json` и каталог рядом.

Сам release APK проверен в Android 9 эмуляторе после обновления с 0.5.30. При свежем кэше HTTP не запускался. Реальный локальный HTTP-сервер дважды оборвал gzip: мгновенный обрыв до сохранения байтов привёл к корректному повтору с нуля; обрыв после сохранения 79099 из 158199 байт привёл к `Range: bytes=79099-` и `If-Range`. Обновление завершилось: 3000 новых передач и 3 сохранённые архивные записи. Во время скачивания старый EPG оставался видимым. После коммита временные файлы удалены; журнал не содержит FATAL EXCEPTION или ANR приложения.

Физический ТВ и скорость источника пользователя в его сети не проверялись. Программный эмулятор работает без KVM; эти результаты не измеряют плавность реального видеопотока.
