# TVNextR 0.5.29 — постоянный EPG и загрузка карточек

Большой EPG больше не собирается целиком в памяти Android и не перечитывается целиком при запуске. Отдельная постоянная база `noBackupFilesDir/epg-index-v1.db` хранит индекс по источнику, каналу и времени. WAL отделяет чтение от импорта и от основной базы настроек/истории.

- Сохранённые передачи читаются по нужным каналам сразу, независимо от HTTP. Свежий индекс повторно не скачивается; TTL 12 часов сохраняется между процессами и при смене суток. Неполный импорт не становится свежим.
- Видимые каналы задают приоритет источников. Их найденные текущие передачи публикуются до конца XMLTV. Импорт пишет по 128 записей с ограничением текстового буфера; работает один поток с фоновым приоритетом. Запросы интерфейса используют отдельные потоки и не ждут импорт.
- Обрыв обновления сохраняет последнюю полную программу. При первом импорте сохраняются уже полученные реальные строки; повторные ошибки ограничены паузой, а не непрерывными загрузками. Архив сохраняется при обновлении скользящего XMLTV.
- Один XMLTV URL скачивается один раз для нескольких плейлистов. Старые `epg_current.dat` / `epg_programs.dat` переносятся потоково без полной загрузки в RAM. XMLTV без отдельных channel-описаний и с пробелами вокруг `=` теперь сопоставляется по tvg-id.
- Стартовая вкладка и настройки читаются до построения дерева экранов. Убрано позднее переключение с экрана каналов на главную. Первичный импорт каталога отличается от отсутствия плейлиста; готовые настройки не запускают повторное добавление исходных источников. Главное меню не обрабатывает всю VOD-библиотеку ради нескольких карточек. Проекции профиля и загрузка Home выполняются вне UI.
- Пункт соотношения сторон и его начальная подпись — «Авто». Исправлено округление 16:9, терявшее пиксель высоты.
- TMDB повторяет временные сетевые и 408/429/5xx ошибки с паузой, не повторяет неверный ключ. Ошибка больше не кэшируется на неделю и не стирает последнюю удачную VOD-карточку. Постер/описание из поиска сохраняются при сбое полной карточки.
- Метаданные одного названия объединяют параллельные запросы; одновременно обрабатываются две карточки. Недостающие поля дополняются из Кинопоиска. Если backdrop отсутствует, используются кадры из документированного `/v1.5/image` по movieId. Частичный ответ сохраняется при тайм-ауте.
- Загрузка изображений ограничена 8 МБ и общим тайм-аутом, повторяет временную ошибку, отменяется при уходе с карточки, отбрасывает HTML и не повторяет 404. Проверены декодирование PNG, память/диск, перезапуск, объединение одинаковых запросов и восстановление повреждённого файла.

Пакет сохранён: `com.tvnext.app.recovery`, версия `0.5.29-recovery-preview`, versionCode 529. Release, debuggable=false, сертификат тот же, что у 0.5.28. Предыдущий APK и исходный ZIP остаются в истории и в дереве репозитория.

Проверки: 345 тестов без ошибок, checkEncoding, assembleRelease/lintVitalRelease, подпись APK v2, zipalign, целостность ZIP. Индекс проверен на реальном SQLite, включая поток из 10 000 записей, повторное открытие базы после закрытия драйвера, отсутствие HTTP при свежем кэше, обрыв XMLTV и чтение во время незаконченной загрузки. Метаданные и изображения проверены через HTTP MockEngine и реальный декодер изображений. Восстановлен отсутствовавший в предоставленном ZIP тестовый M3U из прежней рабочей копии; производственные исходники взяты из последнего ZIP.

Ограничение: сеть окружения запрещает прямые обращения к api.themoviedb.org, api.poiskkino.dev и image.tmdb.org (CONNECT 403). Успешные запросы к живым сервисам с ключами пользователя и поведение на физическом ТВ не подтверждены. API Кинопоиска сверено с официальной документацией https://poiskkino.dev/documentation. Локальные проверки не доказывают доступность сервисов в сети телевизора.
