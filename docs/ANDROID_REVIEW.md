## Реально внесённые изменения

### D-pad, фокус и возврат

- Android-вкладки сохраняются по одной записи в стеке: повторный переход не создаёт дубликат и не уничтожает состояние прежней вкладки. Это сохраняет выбор и фокус при возвращении из гида, поиска и других разделов.
- Восстановление фокуса списка и drawer переведено с индекса строки на ID канала. При удалении/фильтрации канала выбирается доступный выбранный канал, затем первая строка. Выбор другой категории явно переводит фокус вверх.
- Убраны одновременно конкурировавшие Android-эффекты восстановления фокуса и постоянно перехватывавший первую строку специальный FocusRequester.
- В Android раздельные LazyListState для панели каналов и drawer; Android-медиатека больше не использует процессный LazyListState Windows.
- Стрелки в канальном списке немедленно прокручивают к целевой строке и передают фокус после кадра, без очереди анимаций при удержании кнопки.
- Viewport EPG при поиске определяется из фактически отображаемых результатов; drawer также публикует видимые ID.
- Фокус, выбранный канал и фактическое воспроизведение визуально разделены: рамка фокуса, фон выбранного канала и отдельная отметка `▶` для состояния PLAYING.
- Ключи программ таймлайна Android основаны на channelId/start/stop; дубликаты с такой идентичностью исключаются.

### OK и Back

- Back проходит через один Activity dispatcher; повторные ACTION_DOWN при удержании не закрывают несколько уровней подряд. CH+/CH- сохраняют repeatCount, timestamps, flags и источник события при преобразовании в D-pad.
- Back закрывает поиск/категории/активный таймлайн прежде drawer и режима просмотра.
- Android TvCardButton выполняет действие на парный KeyUp; удержание не повторяет действие. Потеря фокуса сбрасывает незавершённое нажатие. Отключённая карточка не реагирует на pointer tap, callback не устаревает после рекомпозиции.
- Для строк каналов долгий OK отменяется при потере фокуса; одиночный KeyUp без своего KeyDown не запускает канал. Долгое нажатие использует актуальный callback избранного.
- Исправлен порядок focus observer/target у Android-видеоконтейнера; автоматический возврат фокуса не вмешивается в открытый таймлайн, поиск или категории.

### PlayerState и Media3

- Сохранены существующие общие PlaybackController, PlaybackItem и PlayerState. Второй модели воспроизведения не создавалось; новые пути используют Channel из core:iptv.
- Добавлен Android PlaybackViewModel — владелец foreground/background-политики плеера и его StateFlow. Activity перестала хранить отдельный backgroundedLiveItem.
- В фоне отменяется retry, снимаются listeners и analytics listener, освобождаются MediaSession и ExoPlayer. Сохраняется item/позиция; при возврате LIVE восстанавливается, VOD/архив подготавливается на сохранённой позиции и остаётся на паузе.
- Повторный вход/выход идемпотентен. У контроллера applicationContext и проверки главного потока. При окончательном закрытии ViewModel освобождает контроллер.
- PlayerSurface только привязывает/отвязывает PlayerView. Создания, release или transport-вызовов ExoPlayer в Composable нет. Descendant focus блокируется.
- Retry имеет отдельный Job и generation; play/pause/stop/release/background отменяют прежнюю попытку. Проверяется полная PlaybackItem, включая URL и archive anchor. Лимит retry больше не сбрасывается при каждом кратком возобновлении воспроизведения.
- Громкость и mute сохраняются при смене канала/вида контента/пересоздании Player. Изменение громкости не снимает mute. Seek ограничивается допустимой позицией и сразу обновляет StateFlow.
- Android-экран каналов отображает название и видеорежим по фактическому PlaybackItem; воспроизведение VOD не выдаётся за ранее выбранный LIVE-канал.

### EPG и архив

- Добавлен AndroidEpgRepository: отдельный LiteEpgRepository и каталог дискового кэша для каждого playlistId/источника. Несколько плейлистов больше не перезаписывают один общий sourceKey и один файл кэша.
- Все обновления сериализованы; refreshPlaylist проходит freshness-проверку. Чтение EPG не начинает сетевую загрузку. Старые engine-записи удаляются при смене источника, отключении/удалении плейлиста.
- У выбранного канала кэш EPG с ограничением 32 записей/30 секунд; у таймлайна — 12 записей/60 секунд. Версия EPG инвалидирует кэши; обновляется и открытый таймлайн. Истечение текущей программы учитывается отдельно от TTL.
- EPG просмотра привязан к реально проигрываемому каналу и archive anchor, независимо от категории и фокуса. Запоздалый результат другого item/версии не публикуется.
- Видимые now-playing результаты объединяются, не стирая остальные уже загруженные каналы. Текущая программа обновляется периодически, без сетевого импорта при перемещении фокуса.
- Отсутствующий дисковый кэш не перечитывается при каждом lookup. Android-импорт публикуется после успешного завершения: неуспешная загрузка не подменяет последний хороший набор частично полученными данными. Прежние программы этого плейлиста заменяются, а не бесконечно накапливаются.
- В Android EPG I/O обрыв чтения не преобразуется в нормальный EOF; потоки закрываются в finally/use, CancellationException пробрасывается. Результат rename кэша проверяется, старый файл не удаляется перед rename.
- Android-проверка доступности архива читает ограниченный префикс потокового ответа, вместо загрузки целого TS/ответа в память.
- Запросы открытия архива отменяются при новом выборе/закрытии; продолжение архива проверяет, что проигрывается прежний item. Запуск архива другого канала обновляет выбранный канал.

### Корутины и состояния экранов

- Android-ветки обработчиков ошибок компонентов, сетевых/архивных репозиториев и EPG не проглатывают отмену корутин. Windows сохраняет прежнюю обработку ошибок.
- У сохранения выбранного канала, отложенного обновления категории, VOD-выбора и TMDB-enrichment появились отменяемые Job.
- На Home, Search и TV Guide новый запрос воспроизведения отменяет предыдущий запрос этого экрана. Android VOD с Home получает правильный kind VOD.
- Закрытие VOD отменяет ожидающий запуск; ID для сохранения прогресса берётся из PlayerState, поскольку reducer уже очистил selectedItemId.
- Android TMDB учитывает ожидающих один запрос: последний ушедший потребитель отменяет запрос и удаляет его запись; очистка выполняется также при отмене await.
- Application использует один принадлежащий ей scope. Ошибка отправки диагностического отчёта не прекращает наблюдение за EPG. Reminder service останавливается/возобновляется с Activity. Compose-callback immersive снимается при disposal.

## Файлы и проверка

`android-review/manifest.json` содержит список изменённых файлов и SHA-256 до/после. Все файлы исходного архива сохранены, включая Windows-часть; добавлены только код, тесты и этот отчёт.

Для полноценной проверки нужны JDK 17, Android SDK Platform 36 и доступ к репозиториям Gradle/Google/Maven:

```sh
bash gradlew :apps:android:assembleDebug --no-daemon
```

На компьютере с Windows можно использовать существующий wrapper без изменения Windows-приложения:

```powershell
.\gradlew.bat :apps:android:assembleDebug --no-daemon
```

Ожидаемый APK после успешной сборки: `apps/android/build/outputs/apk/debug/android-debug.apk` (точное имя проверить в каталоге вывода).

Перед установкой как рабочей версии необходимо проверить на Android TV: удержание стрелок/OK/Back; возврат из гида и поиска; пустые результаты и удалённый канал; переключение LIVE ↔ архив ↔ VOD; Home/возврат/пересоздание Activity; retry с A → B → A; два плейлиста с разными EPG; отмену и обрыв импорта. Профилирование памяти, декодеров и утечек на устройстве не выполнено. Новый формат каталогов EPG не мигрирует старый единый кэш: первое заполнение отдельных источников требует обновления. Атомарный импорт временно держит прежний и новый набор программ; пиковую память на маломощной приставке нужно проверить.

API-справка для ограниченного потокового чтения: https://api.ktor.io/ktor-io/io.ktor.utils.io/-byte-read-channel/index.html
