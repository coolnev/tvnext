# Автофреймрейт TVNext (Android)

Реализовано в 1.0.9. Функция выключена по умолчанию; включается в «Настройки → Воспроизведение → Автофреймрейт». Меняет предпочтения только окна TVNext, без root, разрешений на изменение системных настроек и скрытых vendor API.

## Решения и источники

[Android: Frame rate](https://developer.android.com/media/optimize/performance/frame-rate) описывает точные дробные частоты, кратные режимы экрана, плавную смену и переключения HDMI с временным затемнением. Выбор Android может отличаться от запроса приложения. Для явной смены разрешения/режима на ТВ применяется Window.preferredDisplayModeId. Плавный режим разрешает только альтернативы той же геометрии, о которых сообщает Android, и использует preferredRefreshRate.

[WindowManager.LayoutParams](https://developer.android.com/reference/android/view/WindowManager.LayoutParams) определяет preferredDisplayModeId и preferredRefreshRate. При выходе из просмотра, выключении AFR, потере foreground и уничтожении Activity возвращаются прежние значения этих полей. Пользовательские флаги окна не перезаписываются. После возврата из системных настроек исходный режим считывается заново.

[Media3 ExoPlayer](https://developer.android.com/reference/androidx/media3/exoplayer/ExoPlayer#setVideoChangeFrameRateStrategy(int)) позволяет отключить встроенные запросы частоты поверхности. В TVNext ими управляет один Activity-сеанс AFR; это также сохраняет работу с TextureView для анимации видео. Два механизма не спорят между собой.

[Display.Mode](https://developer.android.com/reference/android/view/Display.Mode) предоставляет физические размеры, частоту и плавные альтернативы (API31+). Список в настройках — сведения Android о текущем экране/HDMI, а не придуманный перечень 24/50/60. Изменение подключённого экрана обновляет список. На старых Android, не сообщающих плавные альтернативы, для смены частоты может понадобиться режим с переключением экрана.

## Подбор и жизненный цикл

- Поддержаны Android API24+. 23.976/29.97/59.94 не округляются до 24/30/60. Режим подходит, если обновление экрана кратно FPS в пределах 0.015 Гц.
- По умолчанию FPS ниже31 по возможности удваивается (25→50, 29.97→59.94). Уже подходящий текущий режим сохраняется. Удвоение можно выключить.
- Смена разрешения отдельно выключена. При включении выбирается ближайшее поддерживаемое разрешение, вмещающее видео без потери пикселей. Плавный режим разрешение не меняет. Если точная частота отсутствует, AFR её не выдумывает; подбор размера может сохранить текущую частоту.
- FPS берётся из входного Media3 Format. Если его нет — из устойчивой выборки PTS кадров, а не скорости UI/сети. Выборка ограничена48 интервалами; повторяющиеся метки, перемотка и переменная кадровая частота не создают ложную оценку. В UI отправляются только изменения оценки.
- Задержка 0.5/1/2/3с объединяет переключения каналов. Старый отложенный запрос отменяется. По умолчанию AFR работает только в полном экране; предпросмотр/главная/гид не вызывают HDMI-переключения.
- Пауза уже настроенного видео и краткая буферизация не возвращают режим туда-обратно. Выход из просмотра, завершение, ошибка, фон и отключение функции возвращают прежние предпочтения окна.
- Отказ устройства применить режим завершается через5с, с возвратом предпочтений. Один и тот же отказ не запускает повторную смену на каждом rebuffer. Ошибки API не завершают приложение.
- Изменения размеров/плотности обрабатываются Activity без пересоздания плеера. Кнопка записи и сервис записи не затрагиваются.

## Значки в нижней панели

Одинаковый порядок в обычной и компактной панелях и полноэкранной панели канала: фактический декодер «А/П» → разрешение → кадры/с → раскладка звука → аудиокодек. Значок Dolby с двойной D обозначает формат выбранной дорожки (AC3, E-AC3/Dolby Digital Plus, TrueHD), а не обещание passthrough, Atmos или сертификации устройства. Неизвестные параметры пропускаются. Для английского интерфейса H/S, для китайского 硬/软.

## Проверяемые пределы

Выбор режимов и PTS проверяются обычными тестами; Android-сеанс, оконные атрибуты, отмена, отказ и восстановление — Robolectric API28/35. UI и пульт — Compose-тестами. Реальное HDMI-переключение, длительность затемнения, vendor-прошивку и аппаратный passthrough можно подтвердить только на телевизоре/приставке. Здесь физического устройства нет.
