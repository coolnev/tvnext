# TVNext 1.0.2 — Android

Пакет **com.tvnext.app**, versionCode **1002**, подпись оригинальной 0.5.21 / 1.0 / 1.0.1. APK `releases/android/TVNext-1.0.2.apk`, SHA-256 `66c582bac1355ec9b5a350bc2b4fa8206c5cdb20a4f85a42af22f36888454ace`. Исходники `33f3282f342f8f63b848e1f856f3a5a1d8e0c71a` в `main`.

В коде найдены несколько причин неполного EPG. Совпадение XMLTV ID одного канала прекращало обработку его названий для остальных вариантов в плейлисте. Теперь сопоставляется каждый канал, используются все display-name, точный tvg-id имеет приоритет. Нормализуются Unicode-пробелы, е/ё, оформление HD/FHD/UHD/4K и суффиксы кодеков. Числовые XML-сущности разбираются корректно: десятичные числа больше не принимаются за шестнадцатеричные, поддерживаются символы вне BMP. Одинаковые локальные ID в разных плейлистах не сливаются. Неоднозначные имена не связываются с произвольным расписанием, знаки часовых сдвигов сохраняются. Схожие названия и номера каналов не считаются совпадением автоматически.

Ручное «Обновить EPG» теперь проверяет покрытие всего плейлиста, включая каналы вне экрана, и дожидается уже запущенной автоматической задачи. Раньше запрос мог ограничиться последними видимыми каналами или сразу вернуть успех, не выполнив ручное обновление. При автоматическом просмотре канал без программы может получить её из резервного источника, даже если основной кэш свежий. Ограничения свежести/повторов сохранены; отсутствие отдельного канала не вызывает повторную загрузку свежего основного файла.

XMLTV допускает отсутствие stop. Раньше такие записи попадали в индекс со stop=0 и не проходили выборку текущих/архивных передач. Теперь окончание определяется по ближайшему следующему началу в том же канале, независимо от порядка XML. SQLite обрабатывает до 512 строк за транзакцию с проверкой отмены, без загрузки всей программы в память. Если следующего начала нет, используется прежний консервативный интервал 30 минут.

После успешного импорта файл XMLTV/gzip сохраняется на срок до суток. Повторный запрос использует If-None-Match / If-Modified-Since: при HTTP304 берётся сохранённый файл, без полного скачивания. Новый ответ200 заменяет файл; ошибочный файл и его валидатор удаляются. Совокупный размер сохранённых исходных файлов ограничен 256МиБ, старые удаляются. Чтение сохранённого файла так и подписывается, без ложного сообщения о скачивании. Если сервер не даёт валидаторы, обычное скачивание остаётся необходимым. Готовый пригодный SQLite-кэш при запуске, как прежде, читается без HTTP. Лимиты обновления и резервные источники из 1.0.1 сохранены.

Пройдены **333 проверки**: 231 IPTV и 102 Android API28/35. Проверены SD/HD-варианты, точные ID, вторые display-name, неоднозначные имена, Unicode/числовые сущности, разные часовые версии, ID разных плейлистов, ручная очередь и каналы вне экрана. Есть тест на 9000 отсутствующих окончаний, SQLite-сценарий с неправильным порядком записей, Android-импорт 1800 каналов / 86400 передач с сохранением архива и реальное локальное HTTP-соединение с обрывом/докачкой. Сквозной Android-сценарий связывает варианты каналов, резерв для невидимого канала, восстановления stop, HTTP304 и открытие кэша новым экземпляром репозитория. Сборка, lintVitalRelease, encoding, Desktop compileKotlin, подпись/zipalign/ZIP и сохранность встроенного ключа прошли. PNG и прямоугольный TV-баннер неизменны.

Физический Google TV и готовый APK в эмуляторе для этой версии не запускались. Основной EPG провайдера недоступен по политике исходящих соединений среды; точное покрытие проблемных каналов не подтверждено, их названия запрошены. Подменять программу приблизительным совпадением или обещать наличие передач, которых нет в источниках, нельзя. Windows-установщик не собирался.
