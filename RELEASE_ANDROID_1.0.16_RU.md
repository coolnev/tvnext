# TVNext 1.0.16 — Android

При включённой анимации на TCL / Google TV пользователь наблюдал повторение нескольких кадров обычных SDR-каналов при нормальном звуке. Выключение анимации устраняло сбой, HDR воспроизводился нормально. **Анимация сохранена**, включая переход 420 мс и TextureView для обычного SD/HD/Full HD SDR. UHD/HDR/защищённое видео сохраняет SurfaceView.

Добавлен обход опасных сбросов аппаратного видеодекодера MediaTek/TCL при выводе в TextureView: перед сбросом позиции, сменой потока, отключением или заменой поверхности декодер освобождается. При переходе с TextureView на SurfaceView учитывается предыдущая поверхность. Отдельная операция догоняющего пропуска до ключевого кадра, вызывающая flush, на этом пути исключена; обычный пропуск поздних кадров сохранён. Для нового источника создаётся новый SurfaceTexture, а при навигации и анимации поверхность сохраняется. Звуковой плеер не пересоздаётся из-за этой защиты.

Основание — [известный обход Media3 1.11.0, b/362904942](https://github.com/androidx/media/blob/1.11.0/libraries/exoplayer/src/main/java/androidx/media3/exoplayer/video/MediaCodecVideoRenderer.java): сброс c2.mtk может необратимо повредить очередь SurfaceTexture. Штатный обход ограничен VideoSink; TVNext использует прямой PlayerView. Это обоснованная гипотеза для описанного сбоя, а не результат измерений на TCL: название декодера и фактическая ошибка устройства здесь не получены.

Для описаний сериалов исправлены приставки **Т/с, T/S, T/С, Т/C** и варианты с точками/пробелами, кавычками и тире. Ранее латинские и смешанные приставки не определяли сериал, а тире могло оставаться в поисковом запросе. Теперь в поиск уходит название без приставки и разделителей; Кинопоиск проверяет тип сериала, TMDB использует поиск и карточку TV. Защита от подмены одноимённым фильмом или новостной передачей сохранена. Решение общее, без особого случая для одного названия. [«Оперативная память» присутствует на Кинопоиске](https://www.kinopoisk.ru/series/5599922/).

**433 автоматических проверок прошли**: 83 Player, 60 метаданных, 107 Channels, 7 Home, 176 Android API 28/35. Новые проверки вызывают настоящие callbacks Media3 с тестовым codec adapter: seek/disable/смена потока/вывода освобождают затронутый декодер без flush, обычные SurfaceView и другие декодеры сохраняют прежний сброс. Проверено подключение renderer во всех режимах звука, возврат из настроек Android и прежние проверки анимации/фокуса. Оба источника описаний проверены HTTP-образцами, включая очищенный запрос и отказ от одноимённого фильма.

Release, lintVitalRelease, encoding, Desktop compileKotlin, подпись и ZIP/zipalign 16 KiB прошли. PNG, Android TV banner и нативные библиотеки совпадают с 1.0.15. Физический TCL/Ugoos здесь недоступен: устранение повторяющихся кадров и плавность требуют проверки на телевизоре. Прямой запрос к API Кинопоиска блокируется сетью среды (CONNECT 403), поэтому реальный ответ API не подтверждён. Windows-установщик не собирался.
