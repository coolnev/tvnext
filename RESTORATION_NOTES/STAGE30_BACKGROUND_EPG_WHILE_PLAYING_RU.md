# TVNext 0.5.21 — этап 30: EPG загружается ВО ВРЕМЯ просмотра

**База:** полный исходный архив этапа 29. Патч накладывается на этап 29. Изменения относятся к Android; функции Windows/desktop и весь UI воспроизведения не изменялись.

## Исправление принципиального поведения этапа 29

В этапе 29 автообновление EPG откладывалось до `PlaybackState.IDLE`, поэтому непрерывный просмотр ТВ мог полностью лишить телепрограмму новых данных. Это поведение отменено.

1. **Видео больше не блокирует импорт**: `AndroidEpgPlaybackGate.canImport` проверяет только передний план приложения, но НЕ `isVideoActive`. Пока идёт эфир, фильм или архив, свежий XMLTV обрабатывается штатно. Отложенное из фона обновление тоже возобновляется при открытии приложения, даже когда сразу началось видео.
2. **Снижение конкуренции за CPU**: XMLTV парсится выделенным Android-потоком `THREAD_PRIORITY_BACKGROUND`. Во время видео парсер делает дополнительные короткие паузы каждые 256 программ; при простое ускоряется. Никакой повторной тяжёлой обработки в UI-потоке.
3. **Кэш без торможения видео**: потоковая запись в `.tmp` выполняется порциями по 64 строки с более длинными паузами при воспроизведении; предыдущий целый кэш сохраняется до успешного `renameTo`. Гид может читать предыдущую версию во время импорта.
4. **Импорт и нормализация**: тяжёлая сортировка и слияние с архивом, а также холодная гидратация кэша при импорте отправляются на выделенный низкоприоритетный worker вместо общего пула корутин.
5. **Резервные источники**: они импортируются последовательно под общим `importLock`, но больше не ожидают выключения видео. UI читает только полностью прогретые резервные источники и не пытается открыть гигантский XMLTV-кэш в момент навигации по каналам.
6. **Защита**: сохранены ограничение памяти для EPG, ограничение описаний больших XMLTV, атомарная запись кэша, cooldown повторных запросов и предыдущая логика архивной глубины. В фоне Activity новый импорт откладывается; видеопоток не трогается.

## Ключевой сценарий

- Запустить LIVE-канал и оставить воспроизведение включённым.
- В настройках выбрать «Обновить EPG», либо дождаться планового обновления.
- XMLTV должен скачиваться/разбираться/публиковаться, не останавливая плеер. EPG-гид должен заполниться после окончания импорта. Большая программа может загружаться медленнее из-за защиты декодера.
- Затем проверить несколько резервных источников, переходы по каналам, поиск и ТВ-гид, архивные даты, закрытие Activity во время загрузки.

## Проверки и ограничения

- Компактный JVM-тест логики gate прошёл: `foreground + videoPlaying = canImport`, background = no import, `awaitForeground()` разблокируется и при включённом видео.
- Статически проверены все `expect/actual` нового метода `paceEpgCacheHydration`; Windows actual — no-op.
- **Полную Android Gradle-сборку и работу на Android TV-боксе в данной среде подтвердить нельзя** (Android SDK/Gradle wrapper distribution недоступны). Обязательно выполнить `:apps:android:assembleRelease` и испытание живого видео на целевом устройстве.
- Нет обещания абсолютного отсутствия рывков на всех устройствах: ресурсы процессора/хранилища общие, но тяжёлая работа теперь низкоприоритетная, ограниченная и выполняется параллельно с видео.

**Важно:** проект не переносится на новую версию архитектуры; изменения сделаны поверх этапа 29, не заменяют `externalNativeBuild` и не удаляют существующие файлы/функции приложения.
