# TVNext — этап 8 восстановления: режимы декодирования Android

Дата: 1 ноября 2026 г.

## База и эталон

Основа — неизменённая в остальном восстановительная база **этапа 7**, которую пользователь попросил продолжать без промежуточных Gradle-сборок. Эталон функциональности и интерфейса — **оригинальный Android TVNext 0.5.21 от 28 октября 2026 г.** Ни одна версия 0.5.22–0.5.27 в качестве основы не использовалась. Это НЕ оригинальные октябрьские исходники.

## Реализовано

1. Android-плеер Media3 использует существующее, уже сохраняемое в SQL, глобальное значение `VideoDecodeMode` из экрана **Настройки → Воспроизведение**, а не дополнительный независимый переключатель.
2. **AUTO** начинает аппаратным MediaCodec; при диагностированной ошибке **видеодекодера** переключается на системный программный MediaCodec. Вторая программная попытка — последняя; бесконечного каскада нет. Сетевые/аудиоошибки не должны переводить видеодекодер в программный режим. В текущем варианте решение о video failure использует `ExoPlaybackException.rendererFormat` либо `rendererName`.
3. **HARDWARE** выбирает только аппаратные видеокодеки; скрытого перехода на ПО нет. **SOFTWARE** выбирает только системные программные видеокодеки. Выбор работает через Media3 `DefaultRenderersFactory` + `MediaCodecSelector`; **аудиодекодеры не фильтруются**.
4. Редактор каналов → настройки выбранного канала: «Из общих настроек», «Автоматически», «Аппаратное», «Программное». Выбор хранится отдельно для профиля и канала. При следующем запуске канала он применяется к Media3; VOD использует глобальный режим.
5. Смена глобального режима во время работы пересоздаёт Media3-плеер. Для VOD/архива выполняется попытка сохранить позицию, а также состояние паузы. Смена настройки отдельного канала применяется при его следующем открытии.
6. Диагностика теперь показывает имя **фактически инициализированного** видеодекодера из события Media3. Пока оно неизвестно, выводится `UNKNOWN`, а не ошибочное `HARDWARE`. Видно запрошенный режим и факт системного fallback в AUTO.
7. Сохранены прежние ограниченные сетевые повторы, логика записи, экранные пропорции и D-pad навигация. Windows/Gradle/native конфигурации не изменены. Суффикс `.recovery` сохранён: тестовая сборка не заменяет эталон 0.5.21.

## Ограничения

- **FFmpeg пока не подключён**. В этом проекте отсутствуют исходные Android-реализация FFmpeg-декодера и его native-сборка; утверждать, что Media3 автоматически перейдёт на FFmpeg, нельзя. Реальная цепочка этого этапа: hardware MediaCodec → system software MediaCodec.
- При ошибке отсутствия видеодекодера без `ExoPlaybackException`/без данных о видеорендерере или при «аудио есть, видео замерло» AUTO может не перейти на программный путь. Эти случаи требуют отдельной инструментальной проверки и доработки.
- Метаданные hardwareAccelerated/softwareOnly на некоторых устройствах до Android 10 являются приближёнными (это ограничение Android/Media3).
- Фактическую работу 4K60, разные аппаратные кодеки, переключение декодеров на реальном TCL и отсутствие регрессий требуется подтвердить **на устройстве**.
- **Полная сборка Android не выполнена** — в этой среде нет Android SDK и Gradle. Синтаксическая проверка и чистый JVM-тест не равны успешной Android-компиляции.

## Одна проверка на агенте

Установить/открыть проект из полного ZIP в **отдельной папке** или наложить патч на точно соответствующий этап 7. Не удалять рабочий этап 7 и оригинальный APK 0.5.21.

```powershell
gradle :apps:android:assembleRelease --stacktrace --console=plain
```

При успешной сборке проверить с пульта только критичные сценарии: глобальные AUTO/HARDWARE/SOFTWARE, переопределение выбранного канала, переключение назад на наследование, архив/VOD-позицию, отсутствие тихого SOFTWARE в HARDWARE, настоящий decoder name в диагностике. **Не публиковать исходный ZIP в публичном репозитории** (в историческом проекте могут быть приватные параметры).
