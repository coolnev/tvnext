# TVNext — восстановление исходников, этап 1 (01.11.2026)

**ВНИМАНИЕ:** это НЕ восстановленные оригинальные исходники TVNext 0.5.21 и не готовая пиксель-в-пиксель копия. Сборка Android из этого архива в текущем окружении не подтверждена. Цель — сохранить настоящий исходный проект и последовательно вернуть недостающую реализацию, не подменяя продукт пустой заглушкой.

## Статус и происхождение

- Эталон: ровно `TVNext-0.5.21-release.apk` от 28 октября 2026, versionCode 35. Он лежит на верхнем уровне ZIP вне исходного проекта. SHA-256: `69e4165379d729dfff81dd800140e04df81f6058c4c5a610fd9617d08e289d0d`.
- Основа исходников: настоящий архив `TVNext3-Android-13-Fixes-Updated2.zip` от 7 сентября 2026, версия 0.2.0; не декомпиляция.
- Сохранили многомодульную структуру `core`, `features`, `apps/android`, `apps/desktop`, основные UI, IPTV, EPG, архив, медиатеку, Media3 и остальные унаследованные классы.
- Windows **не переписывали**; его код из сентябрьской базы сохраняется.
- Изменения после 0.5.21 (0.5.22–0.5.27) не использовались.
- В восстановительном Android-проекте versionName `0.2.0-restore-0521` и versionCode 3: намеренно НЕ `0.5.21`. Debug-сборка имеет ID `com.tvnext.app.recovery`, поэтому не перезапишет установленный эталон.

## Что действительно добавлено на этом этапе

1. Новый `LocalRecoveryStore`: до 8 локальных профилей для записей, разделение записей по владельцу, сохранение метаданных и расписания в приватном хранилище приложения, безопасное удаление только собственной записи, восстановление оборванной записи после аварии.
2. `StreamRecordingEngine`: захват прямого MPEG-TS и HLS без перекодирования; обработка обычных сегментов, AES-128/CBC, EXT-X-MAP, явных BYTE-RANGE. Поддержка отдельных HLS-аудиорендерингов, DRM и MPEG-DASH **отсутствует**. fMP4 и некоторые HLS-сценарии требуют проверки на реальных потоках.
3. `RecordingService`: foreground service с уведомлением и кнопкой остановки, одна запись за раз, ручная максимум 2 ч, по расписанию максимум 6 ч; настройка дискового предела 1–128 ГиБ (по умолчанию 4).
4. `RecordingScheduler`: хранение расписания, AlarmManager, восстановление будущих будильников после перезагрузки. В отсутствие права точных будильников используется неточное планирование; на некоторых версиях Android фоновые ограничения могут помешать запуску.
5. Экспорт записей без их удаления в публичные `Download/TVNext` (MediaStore на API29+) либо в частную экспортную папку на старом Android. ZIP создаётся потоково и без дополнительного сжатия видео.
6. Выбор приложения для сохранения ZIP через ACTION_CREATE_DOCUMENT + системный chooser и актуальная проверка установленного обработчика. При его отсутствии доступно предложение установить AnExplorer. Произвольный USB-каталог для текущей записи пока не реализован.
7. Android UI: на главном экране добавлена кнопка «Мои записи», панель записи открывается также через кнопку MENU пульта. В панели — локальные профили, запись/остановка, простое расписание, сохранение, просмотр локального файла, удаление с подтверждением, лимит хранилища, настройки уведомлений.
8. Удалены старые отправители диагностических сообщений по почте и старый автосбор EPG-диагностики, которые отсутствовали начиная с релиза 0.5.

## ЧТО ПОКА НЕ ВОССТАНОВЛЕНО

- Пиксельная копия интерфейса 0.5.21: темы «Контур», расширенные описания, точные панели, диалоги и фокус всех режимов.
- Глобальные профили 0.5.21 с личными избранным, историей, последним каналом, оформлением, языком, редактором каналов и PIN. Локальные профили этого этапа относятся только к записям.
- Отдельные настройки каждого канала и декодирования, полная последовательная цепочка аппаратный → системный софт → FFmpeg из 0.5.14.
- Сохранённые позиции архивных передач и «Продолжить архив» по профилям, шкала живого эфира в архиве.
- Планирование непосредственно из EPG, запас до/после передачи, конфликты расписаний, точный выбор папок/томов, все события после перезагрузки и системных ограничений.
- Достоверно восстановленные JNI/CMake/NDK-модули 0.5.21. Бинарные библиотеки присутствуют только в исходном эталонном APK, а не реконструированы как C++.
- Все исправления Android TV 0.5.0–0.5.21 (по документам) и весь набор 717 тестов.
- Фактическая сборка, запуск, аппаратный декодер и проверка на реальном TCL.

## Как открыть

Открыть папку с `settings.gradle.kts` в Android Studio. Сентябрьский проект использует JDK 21, AGP 9.1.1, Kotlin 2.4.10 и Gradle Wrapper 9.4.1. Понадобится Android SDK 36. **Не заменять этим проектом установленный эталонный APK 0.5.21**.

```bash
./gradlew :apps:android:assembleDebug
```

Результат предполагаемой сборки: `apps/android/build/outputs/apk/debug/apps-android-debug.apk` (фактическое имя уточнить по выводу Gradle). Отладочный ID `com.tvnext.app.recovery` позволяет установить рядом с оригинальной версией. Сборка Release из этого этапа НЕ предназначена для установки поверх оригинала.
