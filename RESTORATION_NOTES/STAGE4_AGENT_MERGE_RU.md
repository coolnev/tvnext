# TVNext — восстановление: этап 4 (1 ноября 2026 года)

## Что это такое

Это **не исходники оригинальной 0.5.21**. Основа — пользовательский архив `TVnextR-source.zip`, который по сообщению пользователя **собрался у его агента**. Мы не меняли платформенный дизайн или Windows.

**Единственный эталон** — TVNext Android `0.5.21`, versionCode `35`, SHA-256 APK: `69e4165379d729dfff81dd800140e04df81f6058c4c5a610fd9617d08e289d0d`. Изменения из версий 0.5.22+ не переносились.

## Реально объединено из этапа 3

- `core/player/.../PlaybackSeekStep.kt`: JVM-обоснованный выбор шага перемотки.
- `core/player/.../StreamRecoveryPolicy.kt`: две JVM-обоснованные функции для классификации временных ошибок и конца воспроизведения.
- `core/player/.../RecoveredPolicyTest.kt`: тесты этих функций.

Функции перенесены в общий модуль, но **не включены принудительно в существующие цепочки плеера**, чтобы не сломать уже работающее воспроизведение.

## Добавления и исправления поверх сборки агента

1. **Выбор доступного хранилища без проводника:** `RecordingStorageLocations.kt` предоставляет только приложение-зависимые каталоги Android: внутреннюю папку и доступные app-specific папки встроенной памяти/USB. Сохраняется устойчивый токен `app-storage://.../recordings`; произвольные файловые пути из токена не интерпретируются.
2. **Правила безопасности записей:** просмотр, экспорт и удаление проверяют принадлежность текущему профилю и соответствие разрешённому корню. Старые записи остаются на первоначальном накопителе, новые используют выбранный корень. Если накопитель отключили, приложение **не переключается молча** на внутреннюю память.
3. **Профили записей:** переименование существующего профиля с сохранением ID, удаление только неактивного *пустого* профиля. Наличие записей/планов блокирует удаление; никаких скрытых потерь данных. Восстановление безопасного профиля по умолчанию, если JSON повреждён.
4. **Одна запись:** фоновая служба поддерживает приоритет записи по расписанию над ручной. Плановая ждёт завершения ручной (сохранённая часть помечается `partial`), затем занимает слот. При закрытии службы ожидаемая задача не запускается повторно.
5. **Расписание:** запрет пересекающихся плановых записей, отдельный PendingIntent с уникальным URI для каждого ID, восстановление будущих AlarmManager-планов. Без разрешения точного будильника возможна задержка Android.
6. **Экспорт:** при ошибке потоковой записи SAF-ZIP удаляется только созданный неполный экспорт, исходная запись остаётся нетронутой.
7. **HLS:** добавлена поддержка неявного смещения в `#EXT-X-BYTERANGE`, которое вычисляется относительно предыдущего диапазона того же ресурса.
8. **Статус уведомлений** в панели записи и выбор накопителя, кнопки переименования/удаления профиля.
9. **Изоляция релиза восстановления:** в Android `release` выставлен `applicationIdSuffix = ".recovery"`, как ранее в debug; сборка не может обновить или затереть установленную эталонную 0.5.21 с ID `com.tvnext.app`.

Номер восстановления оставлен `0.2.0-restore-0521`, а не `0.5.21`. Исходники и профиль подписания эталона не изменены.

- Kotlin/JVM `RecoveredPlayerPoliciesSmoke.kt`: восстановленные правила плеера — **прошёл**.
- Kotlin/JVM `RecordingScheduleSmoke.kt`: столкновения и границы интервалов — **прошёл**.
- Проверка архива и сопоставление исходников выполнены; `gradlew`, `gradle-wrapper.jar` и версии из проекта агента сохранены.
- **Полная сборка Gradle/Android НЕ запускалась и НЕ подтверждена:** в этом окружении отсутствуют Android SDK и установленный Gradle; доступны только JDK21 и `kotlinc`.

Для проверки у агента (JDK21, SDK36, Gradle из wrapper):

```bash
./gradlew --no-daemon :apps:android:assembleRelease --stacktrace
./gradlew --no-daemon :core:player:allTests
```

В зависимости от Kotlin Multiplatform/AGP корректное имя второй тестовой задачи может отличаться; при необходимости проверить через `:core:player:tasks`.

После компиляции проверить **на Android TV**, не на доверии к описанию: ручная запись HLS/TS, плановая запись поверх ручной, USB-накопитель и его отключение, смена профиля, сохранение ZIP, уведомления, воспроизведение архивов и живые каналы.

## Не восстановлено до стандарта 0.5.21

- Настоящая архитектура октябрьских глобальных профилей (отдельные история, избранное, оформление, редактор каналов, язык, позиции архивов).
- Сложная EPG-интеграция записи по времени конкретной передачи, запас 2/5 минут, полноценное восстановление после принудительной остановки.
- Точный интерфейс/фокус/темы и пиксельное совпадение с эталоном, профили TMDB и декодирование 0.5.14–21.
- Произвольная USB-папка через SAF; сейчас лишь доступные Android приложению каталоги.
- Полный набор тестов оригинальной 0.5.21 и проверка на физическом устройстве.

## Защита пользовательского проекта

Не копируйте этот проект поверх эталонного дерева или установленной 0.5.21. Не публикуйте ZIP: в первоначальных файлах пользователя могут присутствовать приватные реквизиты и адреса источников. `local.properties`, `.kotlin` и вложенный патч-архив удалены как машинные/временные данные; всю Gradle-конфигурацию и wrapper сохранено. Native/Windows-код из загрузки пользователя не менялся. В данной базе отсутствует `externalNativeBuild`, добавлять несуществующую конфигурацию мы не стали.
